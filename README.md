# NIVORA BOOKING — Flutter v1.0.2 (CI Repair & Commit Check)

A premium-looking Indonesian booking UI prototype made with Flutter. Dark midnight blue, neon-lime and lilac accents, with rich listing views and a functioning *local-demo* booking flow.

> **Important:** This app does **not** sell hotel inventory, call reservation APIs, reserve actual rooms, or process payments. All listings, ratings, reviews, offers, prices and booking confirmations are fictional demo data. The QR embeds a local demo identifier only. The map graphic is a decorative illustration, not live geolocation.

## Features

- Discover: hero promotion, trending stays, category shortcuts, curated destination listings.
- Explore/search: live keyword search (name, city and category), category chips, price and ratings filters, sort by price or rating.
- Listings: imagery, reviews/rating UI, amenity chips, highlights, host info and illustrated map.
- Favorites: heart buttons + persistent favorites across app launches.
- Booking flow: date-range picker, guest counter, promo code `NIVORA10`, real-time price summary, simulated payment selection.
- Trips: upcoming and historical booking tabs, ticket view, local cancellation and notifications.
- E-ticket: booking ID, QR, dates, guests, totals, copy booking code.
- Profile: rewards demo, counters, dark mode and notification preference persisted locally.
- Indonesian language and IDR price formatting. Responsive, Material 3, supports dark/light.

## Technology

- Flutter (Dart 3.8+), Material 3
- `shared_preferences` for non-critical local demo preferences and booking records
- `qr_flutter` for offline rendering of demo QR codes
- Hotel photography requested over HTTPS from Unsplash when online; gradient fallback when offline. Photos and listing names are not asserted to represent actual properties.
- No backend or API key is required for the demo. This is an extensible frontend, not an operational hotel reservation engine.

## Run on a Flutter-equipped computer

```bash
flutter create --platforms=android --org=com.nivora --project-name=nivora_booking .
python3 scripts/configure_android.py
flutter pub get
flutter run
```

Note: The ZIP intentionally includes source code instead of generated `android/` Gradle boilerplate. `flutter create` reliably generates that boilerplate matching your installed Flutter version while leaving source files intact.

## Build APK on a phone using Termux + GitHub Actions

Save the ZIP file under Android `Download/` and open Termux:

```bash
pkg update -y && pkg upgrade -y
pkg install -y git gh unzip
termux-setup-storage
cd ~
unzip -o /sdcard/Download/NivoraBooking-v1.0.2-CI-Fix.zip
cd NivoraBooking
git init
git branch -M main
git add .
git -c user.name="Nivora Builder" -c user.email="builder@example.com" commit -m "Initial Nivora Booking Flutter"
gh auth login
gh repo create nivora-booking --public --source=. --remote=origin --push
```

The `Build Nivora Android APK` workflow runs automatically on the first `main` push. Alternatively, open the GitHub repository in a mobile browser, choose **Actions → Build Nivora Android APK → Run workflow**. When the run finishes, download the `NivoraBooking-v1.0.2-APK` artifact and unzip it to find `app-release.apk`. The APK uses GitHub's autogenerated Android debug-style release signing when there is no personal release key configured; configure your own signing for a production launch.

To update later:

```bash
cd ~/NivoraBooking
git add . && git commit -m "Update Nivora" && git push
```

## v1.0.1 hotfix — GitHub Actions `MyApp` error

Previous releases had no `test/widget_test.dart` in the ZIP. When GitHub Actions
ran `flutter create ... .`, Flutter added its own template test calling
`const MyApp()`, but this application starts with `NivoraApp(controller: ...)`.
As a result, `flutter test` exited with code 1 and stopped the APK build.

This version ships `test/widget_test.dart` that instantiates the real app and
verifies navigation. The workflow also detects and removes an old template
`const MyApp()` test if Flutter happens to create it. GitHub actions checkout and
setup-java have been upgraded to their Node.js 24-compatible v5 releases.
The workflow pins `ubuntu-24.04` so the GitHub runner OS does not change unexpectedly.

To update an **existing Git repository** using a phone with Termux, copy the new
ZIP into Android Download/ and run:

```bash
cd ~
unzip -o /sdcard/Download/NivoraBooking-v1.0.2-CI-Fix.zip
cd ~/NivoraBooking
git status
git add .github/workflows/build-apk.yml test/widget_test.dart pubspec.yaml README.md
git commit -m "Fix Flutter autogenerated MyApp test and workflow warnings"
git push origin main
```

If the old repository uses the `master` branch, substitute `main` with `master`.
After push, open GitHub > Actions > Build Nivora Android APK, and download the
`NivoraBooking-v1.0.2-APK` artifact if the run succeeds.

If `git commit` says author identity is unknown, configure `git config
user.name` and `git config user.email` first. The new ZIP contains source, not
a prebuilt APK. GitHub must run the test and release-build steps successfully.

## v1.0.2: fix for GitHub still using the OLD workflow / MyApp test

The error `test/widget_test.dart: Couldn't find constructor MyApp` means GitHub
executed an old test from the repository or the Flutter scaffold-generated sample.
The previous v1.0.1 ZIP already had the correct `NivoraApp` test: if your Actions
logs still show `checkout@v4`/`setup-java@v4`, you are viewing an older run,
or the ZIP's fixes were not pushed to the branch used by the workflow.

This version adds:
- `scripts/repair_widget_test.py` to replace only a missing or stale
  autogenerated `MyApp` widget test after `flutter create`.
- A committed canonical `scripts/ci_widget_test.dart` template.
- A Git revision/version diagnostic step in Actions, to prove which push
  and version the run actually uses.
- APK artifact `NivoraBooking-v1.0.2-APK`.

### Update the **existing** GitHub repo from Termux

First place ZIP in Android Download, then run:

```bash
pkg install -y git unzip
termux-setup-storage
cd "$HOME"
unzip -o /sdcard/Download/NivoraBooking-v1.0.2-CI-Fix.zip -d "$HOME"
cd "$HOME/NivoraBooking"
git status
git add -A
git -c user.name="Nivora Builder" -c user.email="builder@example.com" commit -m "Nivora v1.0.2 fix GitHub MyApp test"
git push origin "$(git branch --show-current)"
```

If `git status` prints `not a git repository`, you are in a fresh
project directory, not your existing clone. Copy the ZIP contents into your
existing clone first. Do **not** run `git init` or `gh repo create` again.

Ensure the GitHub Actions run is from the NEW commit. Check the `Verify pushed
revision` step: `Version: version: 1.0.2+3` and the printed commit hash must
match `git rev-parse HEAD` in Termux. Do **not** click `Re-run jobs` for the
old failed run; that reuses the old commit. Instead push to your branch or
choose Actions > Run workflow on the updated branch.

If no changes are detected when you run `git commit`, run `git status`,
`grep '^version:' pubspec.yaml`, and `git remote -v`; this verifies you
updated the correct folder/repository.

This source has been structurally checked locally, but Flutter tests and
Gradle compilation still need a runner with Flutter installed.
