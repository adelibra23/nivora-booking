# NIVORA BOOKING — Flutter v1.0.0

A premium-looking Indonesian booking UI prototype made with Flutter. Dark midnight blue, neon-lime and lilac accents, with rich listing views and a functioning *local-demo* booking flow.

> **Important:** This app does **not** sell hotel inventory, call reservation APIs, reserve actual rooms, or process payments. All listings, ratings, reviews, offers, prices and booking confirmations are fictional demo data. The QR embeds a local demo identifier only. The map graphic is a decorative illustration, not live geolocation.

## Features

- Discover: hero promotion, trending stays, category shortcuts, curated destination listings.
- Explore/search: live keyword search (name, city and category), category chips, price and ratings filters, sort by price or rating.
- Listings: imagery, reviews/rating UI, amenity chips, highlights, host info and illustrated map.
- Favorites: heart buttons + persistent favorites across app launches.
- Booking flow: date-range picker, guest counter, promo code `NIVORA10`, real-time price summary, simulated payment selection.
- Trips: upcoming and historical booking tabs, ticket view, local cancellation and notifications.
- E-ticket: booking ID, QR, dates, guests, totals, copy booking code.
- Profile: rewards demo, counters, dark mode and notification preference persisted locally.
- Indonesian language and IDR price formatting. Responsive, Material 3, supports dark/light.

## Technology

- Flutter (Dart 3.8+), Material 3
- `shared_preferences` for non-critical local demo preferences and booking records
- `qr_flutter` for offline rendering of demo QR codes
- Hotel photography requested over HTTPS from Unsplash when online; gradient fallback when offline. Photos and listing names are not asserted to represent actual properties.
- No backend or API key is required for the demo. This is an extensible frontend, not an operational hotel reservation engine.

## Run on a Flutter-equipped computer

```bash
flutter create --platforms=android --org=com.nivora --project-name=nivora_booking .
python3 scripts/configure_android.py
flutter pub get
flutter run
```

Note: The ZIP intentionally includes source code instead of generated `android/` Gradle boilerplate. `flutter create` reliably generates that boilerplate matching your installed Flutter version while leaving source files intact.

## Build APK on a phone using Termux + GitHub Actions

Save the ZIP file under Android `Download/` and open Termux:

```bash
pkg update -y && pkg upgrade -y
pkg install -y git gh unzip
termux-setup-storage
cd ~
unzip -o /sdcard/Download/NivoraBooking-v1.0.0.zip
cd NivoraBooking
git init
git branch -M main
git add .
git -c user.name="Nivora Builder" -c user.email="builder@example.com" commit -m "Initial Nivora Booking Flutter"
gh auth login
gh repo create nivora-booking --public --source=. --remote=origin --push
```

The `Build Nivora Android APK` workflow runs automatically on the first `main` push. Alternatively, open the GitHub repository in a mobile browser, choose **Actions → Build Nivora Android APK → Run workflow**. When the run finishes, download the `NivoraBooking-v1.0.0-APK` artifact and unzip it to find `app-release.apk`. The APK uses GitHub's autogenerated Android debug-style release signing when there is no personal release key configured; configure your own signing for a production launch.

To update later:

```bash
cd ~/NivoraBooking
git add . && git commit -m "Update Nivora" && git push
```
